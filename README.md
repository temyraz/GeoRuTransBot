# Telegram-бот: переводчик грузинского транслита

Бот переводит между тремя вариантами письма/языка с помощью Gemini API
(модель `gemini-3.6-flash`), даёт краткий разбор фраз, хранит личный словарь
сохранённых переводов и присылает шпаргалку по транслиту.

## Режимы перевода

1. **GEO Translit ➡️ RU** (режим по умолчанию) — грузинский чат-транслит
   (карто-латиница, например `Gacnobebt, rom ganaxlda...`) → русский.
2. **RU ➡️ GEO Translit** — русский текст → грузинский чат-транслит.
3. **GEO Translit ➡️ ქართული** — грузинский транслит → грузинский алфавит
   (мхедрули).

Режим переключается командой `/settings` через inline-клавиатуру и хранится
отдельно для каждого пользователя.

## Тональность перевода

Там же, в `/settings`, можно выбрать тональность для режимов (1) и (2):

- 👔 **Официальный** — формулы вежливости, Вы-форма, терминология банков,
  госучреждений и юридических документов.
- 💬 **Разговорный** (по умолчанию) — естественная разговорная речь, как в
  мессенджерах.

Тональность подмешивается в системный промт Gemini дополнительной инструкцией
(`OFFICIAL_STYLE` / `CASUAL_STYLE` в `prompts.py`). Для режима (3), где нет
перевода как такового (только смена алфавита), тональность не применяется.

## Кнопки под переводом

- **🇬🇪 На грузинский алфавит** (только режим 1) — мгновенно дописывает к
  сообщению исходную фразу буквами мхедрули.
- **🔍 Разбор** (только режим 1) — короткий разбор: тон фразы, нюансы и
  контекст, ключевые слова с переводом. Присылается отдельным сообщением.
- **⭐ Сохранить** (все режимы) — сохраняет пару «исходный текст → перевод» в
  личный словарь пользователя.

## Личный словарь (`/dictionary`, кнопка «📚 Мой словарь»)

Сохранённые фразы хранятся в SQLite (таблица `vocabulary`: `id`, `user_id`,
`original_text`, `translated_text`, `created_at`) и доступны по команде
`/dictionary` или кнопке **«📚 Мой словарь»** в меню под полем ввода — список
с пагинацией (по 5 записей на страницу) и кнопкой удаления у каждой записи.

## Шпаргалка транслита (`/alphabet`, кнопка «📖 Шпаргалка транслита»)

Статичное сообщение-справочник по самым частым буквосочетаниям (kh, dz, ts,
ch, sh, gh, zh) — отправляется мгновенно, **без** обращения к Gemini.

> **Про модель:** изначально в проекте использовалась `gemini-2.5-flash`, но
> Google закрыла доступ к ней для новых пользователей API — при вызове
> возвращается `404 NOT_FOUND` с рекомендацией переходить на
> `gemini-3.6-flash`. Именно эта модель используется сейчас. Если у вас
> появится похожая ошибка `404 NOT_FOUND` с упоминанием другой модели —
> обновите константу `GEMINI_MODEL` в `main.py` на модель, указанную в тексте
> ошибки (актуальный список моделей: https://ai.google.dev/gemini-api/docs/models).

## Структура проекта


## Установка

1. Склонируйте/скопируйте проект и перейдите в его директорию.

2. Создайте и активируйте виртуальное окружение (рекомендуется):

   ```bash
   python -m venv venv
   source venv/bin/activate      # Linux / macOS
   venv\Scripts\activate         # Windows
   ```

3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Скопируйте `.env.example` в `.env` и заполните значения:

   ```bash
   cp .env.example .env
   ```

   ```env
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   GEMINI_API_KEY=ключ_от_Gemini_API
   DATABASE_PATH=bot.db
   ```

   - `TELEGRAM_BOT_TOKEN` — получить у [@BotFather](https://t.me/BotFather) (`/newbot`).
   - `GEMINI_API_KEY` — получить в [Google AI Studio](https://aistudio.google.com/apikey).
   - `DATABASE_PATH` — необязательно, путь к файлу SQLite для словаря (см.
     ниже про персистентность на Railway).

## Запуск

```bash
python main.py
```

При первом запуске автоматически создаётся файл SQLite (таблица `vocabulary`).
Бот запустится в режиме long polling. Отправьте ему `/start` — появится меню
с кнопками словаря и шпаргалки, а также подскажет текущий режим/тональность.
Команда `/settings` открывает переключатель режима и тональности.

## Деплой в облако, чтобы бот работал 24/7 без вашего компьютера

Бот использует long polling (сам стучится к Telegram), поэтому ему не нужен
открытый HTTP-порт и статический IP — подходит почти любой облачный хостинг,
который умеет запускать Docker-контейнер или произвольный процесс. Ниже —
самый простой вариант: **Railway**.

> Почему Railway: он умеет запускать «background worker» (процесс без
> публичного URL) прямо из `Dockerfile`, не требует карты для старта и на
> практике такой лёгкий бот укладывается в пару долларов в месяц. Render.com
> тоже подойдёт, но там background worker (без HTTP-порта) доступен только на
> платных планах от $7/мес — на Render бесплатен только полноценный «Web
> Service», которому нужен открытый порт.

### Вариант A — через GitHub (проще всего)

1. Создайте репозиторий на GitHub и залейте туда все файлы проекта **кроме**
   `.env` и `*.db` (они и так игнорируются через `.gitignore` — реальные
   токены и локальная база не должны попадать в репозиторий).
2. Зайдите на [railway.com](https://railway.com), зарегистрируйтесь (можно
   через GitHub, без карты).
3. **New Project → Deploy from GitHub repo** → выберите ваш репозиторий.
   Railway сам увидит `Dockerfile` и соберёт образ.
4. Откройте вкладку **Variables** созданного сервиса и добавьте:
   - `TELEGRAM_BOT_TOKEN` = ваш токен от BotFather
   - `GEMINI_API_KEY` = ваш ключ Gemini API
5. Дождитесь окончания деплоя (вкладка **Deployments**) и откройте
   **Logs** — там должна появиться строка `Бот запущен, начинаю polling...`.
6. Готово — бот работает в облаке и отвечает независимо от того, включён ли
   ваш компьютер.

Если у сервиса включена генерация публичного домена (Settings → Networking) —
её можно отключить, она не нужна для этого бота.

### Вариант B — через Railway CLI (без GitHub)

```bash
npm install -g @railway/cli   # или через brew/curl — см. docs.railway.com
railway login
cd telegram-georgian-translator
railway init
railway variables --set "TELEGRAM_BOT_TOKEN=ваш_токен" --set "GEMINI_API_KEY=ваш_ключ"
railway up
```

Railway соберёт образ по `Dockerfile` из текущей папки и задеплоит его.

### Персистентность словаря на Railway (важно!)

Диск контейнера на Railway (и большинстве PaaS) **эфемерный**: при каждом
редеплое или перезапуске сервиса файл SQLite создаётся заново, и весь
сохранённый словарь пользователей пропадает. Чтобы этого избежать:

1. В Railway откройте сервис → **Settings → Volumes → New Volume**, укажите
   путь монтирования, например `/data`.
2. Добавьте переменную `DATABASE_PATH=/data/bot.db` во вкладке **Variables**.
3. Передеплойте сервис — теперь файл БД лежит на постоянном диске и
   переживает редеплои.

Без подключённого volume бот продолжит работать нормально — просто словарь
будет сбрасываться при каждом обновлении кода на Railway. Для локального
запуска и Docker без volume это не проблема — файл просто лежит на диске
компьютера/контейнера между запусками.

### Обновление бота после изменений в коде

- Вариант A: просто сделайте `git push` в тот же репозиторий — Railway
  задеплоит новую версию автоматически.
- Вариант B: повторите `railway up` из папки проекта.

### Локальная проверка Docker-образа (по желанию)

Перед деплоем можно проверить, что контейнер собирается и запускается локально:

```bash
docker build -t georgian-translator-bot .
docker run --env-file .env georgian-translator-bot
```

## Как это работает

1. Пользователь отправляет текстовое сообщение боту.
2. Бот смотрит, какой режим и тональность сейчас выбраны у этого
   пользователя (по умолчанию — GEO Translit ➡️ RU, разговорный стиль), и
   собирает системный промт (`build_system_prompt` в `modes.py`).
3. Текст уходит в Gemini (`gemini-3.6-flash`) вместе с этим промтом; модель
   отвечает **только** готовым результатом — без пояснений и исходного текста.
4. В режиме GEO Translit ➡️ RU бот отвечает сообщением вида
   `Транслит: ...` / `Перевод: ...` с кнопками «На грузинский алфавит» и
   «Разбор». В двух других режимах бот присылает просто готовый результат.
   Под любым переводом есть кнопка «⭐ Сохранить».

### Кнопка «На грузинский алфавит» и «Разбор»

Обе кнопки достают исходный текст и перевод, парся их регулярным выражением
прямо из текста сообщения бота (метки `Транслит:` / `Перевод:`) — поэтому
продолжают работать даже после перезапуска бота, без отдельного хранилища.
«На грузинский алфавит» дописывает строку `Мхедрули: ...` в то же сообщение
(`edit_text`). «Разбор» вызывает Gemini с промтом `EXPLAIN_PROMPT` и
присылает результат новым сообщением; после этого кнопка заменяется на
неактивную «✅ Разбор», чтобы повторный клик не тратил лишний запрос к API.

### Кнопка «⭐ Сохранить»

Работает во всех трёх режимах. Так как во 2-м и 3-м режиме сообщение бота не
размечено метками (это чистый результат, как и было задумано), исходный
текст и перевод для этой кнопки берутся из короткоживущего кэша в памяти
процесса (`pending_translations` в `main.py`, ключ — `(chat_id, message_id)`,
ограничен 2000 записями). **Ограничение:** если бот перезапустится, кнопка
«Сохранить» под уже отправленными сообщениями перестанет работать (ответит
подсказкой «отправьте фразу ещё раз») — для новых переводов после перезапуска
всё работает как обычно.

### Переключение режима и тональности (`/settings`)

Присылает inline-клавиатуру: 3 кнопки режима + 2 кнопки тональности, текущий
выбор помечается ✅. Хранится в двух словарях в памяти процесса (`user_modes`,
`user_tones` в `main.py`), отдельно по `user_id`. Это самый простой вариант
для одного/нескольких пользователей; **при перезапуске бота выбор сбрасывается
на значения по умолчанию для всех**. Если бот будет использоваться многими
людьми и это станет проблемой — стоит перенести оба словаря в ту же таблицу
SQLite, что и словарь фраз (отдельная небольшая доработка).

## Обработка ошибок

- Все ошибки при обращении к Gemini API логируются (`logging`, уровень ERROR,
  со стектрейсом) и не приводят к падению бота.
- Пользователь при сбое получает вежливое сообщение об ошибке и может
  повторить попытку.
- Превышение квоты Gemini API (`429 RESOURCE_EXHAUSTED`) распознаётся
  отдельно (`user_facing_gemini_error` в `main.py`) и показывает пользователю
  понятное сообщение про лимит, а не общую ошибку.
- Ошибки сохранения в словарь (БД недоступна и т.п.) логируются и не мешают
  показать перевод — пользователь просто увидит уведомление о неудачном
  сохранении.
- При отсутствии `TELEGRAM_BOT_TOKEN` или `GEMINI_API_KEY` бот завершает
  работу при старте с понятным сообщением в логах.

### Лимиты бесплатного тарифа Gemini API

У бесплатного тарифа Gemini API есть суточная квота запросов (Requests Per
Day) на комбинацию проект/модель — для новых моделей вроде `gemini-3.6-flash`
она может быть очень маленькой (например, 20 запросов в сутки). Каждый
перевод, нажатие «На грузинский алфавит» и «Разбор» — это отдельный запрос.
Квота обновляется в полночь по тихоокеанскому времени (США). Текущие лимиты
для конкретного ключа/модели видны на
[странице лимитов в Google AI Studio](https://aistudio.google.com/rate-limit).

Если бот нужен для реального ежедневного использования, а не для тестов —
стоит подключить платный (pay-as-you-go) тариф в Google AI Studio /
Google Cloud Console: лимиты вырастают на порядки, а стоимость для такого
лёгкого текстового бота обычно составляет доли цента за перевод.

## Заметки

- Модель Gemini вызывается асинхронно (`client.aio.models.generate_content`),
  чтобы не блокировать event loop aiogram.
- Все системные промты (3 режима перевода, `EXPLAIN_PROMPT`, `OFFICIAL_STYLE`,
  `CASUAL_STYLE`) собраны в `prompts.py` — их можно скорректировать под свои
  нужды в одном месте.
- Записи словаря удаляются с проверкой владельца (`user_id`) — один
  пользователь не может удалить запись другого, даже если бы подобрал её id.
- Сообщения, начинающиеся с `/` и не совпадающие с известными командами, бот
  не отправляет в Gemini, а отвечает подсказкой по доступным командам.
