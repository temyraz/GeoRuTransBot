# Оптимизация производительности бота — Перечень изменений

## ⚡ 3 основных улучшения

### 1️⃣ **Кэширование переводов с TTL** (cache.py)
Система кэша хранит переводы на 1 час. Повторный запрос одной и той же фразы выполняется мгновенно, без обращения к API.

**Параметры:**
- Размер кэша: 5000 записей
- TTL: 3600 секунд (1 час)
- Ключ: (режим, тональность, текст)

**Эффект:** Вторая попытка перевода → ~0 сек вместо 2-5 сек

---

### 2️⃣ **Таймауты для API** (main.py)
Каждый запрос к Gemini или Google Translate имеет временной лимит:
- **Gemini:** 15 секунд
- **Google Translate:** 10 секунд

Если API не отвечает в срок, система автоматически переключается на альтернативный провайдер (фоллбэк).

**Эффект:** Нет бесконечного ожидания; предсказуемое время ответа

---

### 3️⃣ **Дедупликация параллельных запросов** (deduplicator.py)
Если 10 пользователей одновременно отправят одинаковый текст → выполнится **только 1 API-запрос**, остальные дожидаются результата.

**Сценарий:**
```
User1: "привет" → Gemini API (1-й запрос)
User2: "привет" → ждёт результата от User1
User3: "привет" → ждёт результата от User1
...
User10: "привет" → ждёт результата от User1

Результат: 1× вызов Gemini вместо 10× ⚡
```

**Эффект:** На пиковой нагрузке снижение нагрузки на API в 10× и более

---

## 🚀 Как работает

### Типичный сценарий (первый перевод)
```
1. Пользователь отправляет фразу
2. handle_text() проверяет кэш → пусто
3. deduplicate_translation_request() проверяет, нет ли параллельных запросов
4. Выполняется translate_geo_to_ru_smart()
5. API-запрос к Gemini/Google (с таймаутом)
6. Результат кэшируется на 1 час
7. Ответ отправляется пользователю
```

### Вторая попытка той же фразы (через 5 минут)
```
1. Пользователь отправляет ту же фразу
2. handle_text() проверяет кэш → НАЙДЕНО! ✅
3. Мгновенный ответ (~0 сек), без API-запроса
```

### Параллельные одинаковые запросы (10 пользователей одновременно)
```
User1: отправляет "привет"
  → кэш пуст
  → дедупликатор: создаёт Event для ("GEO_RU", "casual", "привет")
  → API-запрос Gemini...

User2-10: отправляют "привет"
  → кэш пуст
  → дедупликатор: видит Event, ждёт готовности
  → когда User1 получит результат → все User2-10 получают тот же результат

Результат: 1 API-вызов для 10 пользователей 🎉
```

## ⚠️ Важно

- **Кэш в памяти процесса** — при перезапуске бота кэш очищается
- **Для распределённых систем** — если несколько инстансов бота, кэш не будет общим (рекомендуется Redis)
- **Таймауты** — настроены консервативно, может потребоваться корректировка для медленных сетей
